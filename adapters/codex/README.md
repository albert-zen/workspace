# Codex 接入说明

这里只记录在 Codex Harness 中工作时已观察到的局部差异与临时补偿；通用协作与 Review 方式见 [协作与上下文](../../practices/collaboration.md) 和 [独立 Review](../../practices/review.md)。

## 已知特性与注意事项

- **上下文压缩后的行为**：Codex 在历史压缩时会将线程间消息计入用户消息，且压缩后不会自动重新读取最新 `AGENTS.md`。长会话压缩后如果规则或目标有变化，先重新核对入口文件或运行 `work resume`。
- **工具与模型配置以当前环境为准**：派发子任务、创建 worktree、安排定时跟进或指定模型时，按当前 Harness 实际提供的工具能力和本次任务要求选择，不写死过时的模型代号或绕过工具权限边界。
- **异步回收与跟进**：启动独立子任务或后台自动化后，把真实任务标识、恢复入口和停止条件记在 Work 里；结束任务时顺手停掉不再需要的定时跟进。

## 当前临时补偿（随模型升级定期复核并拆掉）

按 [园丁原则](../../garden.md) 将模型代际偏置与长期规则分开，以下条目在后续模型升级不再复现对应问题时可直接删除：

- **不要因“去 AI 腔”压平排版结构**：近几代 GPT/Codex 模型容易把“少用套话、去 AI 腔”误读为删掉标题和缩进列表，输出大段平铺散文墙。请严格保留 [沟通与呈现](../../practices/communication.md) 的首行结论、左缘标题/列表、短段落和独立拍板块。*（来历：实际长对话中重点埋在散文中间；退场条件：新模型仅凭通用规则即可稳定输出可扫读版式。）*
- **不要在已授权目标的中间结果反复停手**：近几代 GPT/Codex 在写操作和长流程上偏保守，容易出现“查完不改”“改一半留一半”“把带催促意图的反问（例如‘更新有什么难点？’）当成纯只读科普”，导致多轮重复对话。只要目标已明确授权、且标准工程方案可以通过备份或安全隔离方式落地，直接推进到完成并附带验证证据，只在真正不可逆或存在真实业务分歧时停下来问。*（来历：实际交付中多次因过度确认造成重复催促；退场条件：新模型不再出现无必要的半截交差。）*
