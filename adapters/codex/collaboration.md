# Codex 协作工具的使用

通用职责见[事项推进](../../practices/collaboration/work.md)与[Review](../../practices/collaboration/review.md)。Worker、Reviewer 和 Chief 是职责；侧栏任务与内部 subagent 是不同执行环境。根据用户要求、上下文与当前工具能力选择，不让工具名字定义组织架构。

## 创建与隔离

用户明确要求新的侧栏任务时使用相应任务工具。当前工作的有界子任务按内部 subagent 工具的授权条件执行；“需要 Reviewer”本身不自动意味着用户要求一个新的侧栏任务。工具不支持或当前指令不允许的委派，不通过换一种调用方式绕过。

侧栏项目任务先解析真实项目，再使用工具支持的环境。Git 写入默认使用 worktree，遵从用户明确选择。只读审查也需要项目规则与固定对象；若当前工具无法复用指定 worktree，就取得支持的安全隔离版本，不靠长提示词假装改变了创建参数。

内部 subagent 可能共享目录，依据当前环境检查。并行代码写入隔离，共享文档也分配写入责任。任务提示词给出可独立执行的结果与必要上下文，不强制填写不适用的侧栏字段。

运行配置按用户当前要求、Work 已确认配置、工作空间默认值的顺序选择。沿用当前的成本与判断能力偏好：Reviewer、QA 和边界清楚的 Worker 使用 Luna 与平台默认思考强度；需要综合实现判断的 Worker 使用 Sol Medium，最复杂的长期架构工作使用 Sol High。不开启快速模式。这是可调整的运行偏好，不是这些模型永久具有某种能力的断言。

工具支持且允许指定配置时，创建者显式传入已选模型与思考强度，并依据调用与可读状态核对项目、环境及运行配置；执行者不凭自身身份描述猜测精确模型。既定配置不受支持时说明差异，不静默替换。尚未执行就发现不符时先修正；已经产生结果时在 Work 记录计划值、实际值、影响及处理决定，不掩盖偏差。

派发内容按[共同上下文](../../practices/collaboration/context.md#各环节共同遵守的最少约定)，将其中的目录、任务标识与返回通道落实为当前工具能使用的值，不填不适用的侧栏字段。

## 回收结果

创建可能异步完成，保存返回的真实任务标识，取得启动状态。尚未就绪的临时 ID 不能传给要求正式任务 ID 的工具。活动任务跨回合时，把实际入口和下一步写进 Work。

内部 subagent 使用原生返回、消息和等待；完成、失败或阻塞时按派发契约通知直接上级，原生最终返回已投递时不重复发送相同报告。侧栏任务使用当前可用的状态等待与读取，取得变化后再读完整报告。已有 cursor 或增量位置时继续使用，避免反复读取相同历史；等待保持有界，给用户留下响应空间。

发送到另一个侧栏任务的消息可能使它运行。只有已有明确消息授权时才发送；完整报告保留在来源，消息传足以定位的状态与对象即可。没有发送授权时通过读取或等待回收，不能把没有发出 DONE 信号当作无法继续。

Chief 的普通状态同步默认拉取相关变化，避免无关项目进度抢占前台对话。用户要求即时通知或当前环境提供不打断前台的通知通道时，按实际能力安排。短消息的作用是减少重复内容和打断，不把未经复验的压缩机制解释写成永久事实。

## 在实际任务层级中咨询

咨询与决定回流按[事项推进](../../practices/collaboration/work.md#设计问题逐层咨询)。内部 subagent 使用允许的原生通道；侧栏任务在已有消息授权时发送问题摘要与来源，由上级读完整依据。返回目标以派发契约为准，不凭名称猜测。

减少普通进度打断不等于禁止咨询。没有请求通道时，把待咨询问题和受影响节点保存在入口，交当前能接手的负责人读取；BLOCKED 状态不等于取得答复，工具投递成功后才说已发送。答复通过可用通道通知执行者；跨 Harness 无法读取来源时提供必要交接材料。

## 稍后继续与自动化

用户要求稍后继续、监控、提醒或持续跟进时，用当前自动化工具落实，优先复用适用的当前任务 Heartbeat。提示词只说明目标、恢复入口、通知与停止条件，计划留在 Work；无可行动变化时保持安静。Work 的 pause/cancel/reopen/finish 只同步记录和 Inbox 视图，不代替自动化工具停止、暂停或中断 Agent；需要调整运行时由 Agent 或对应调度工具单独处理。

活动子任务优先在当前回合回收。交还控制权前核实谁会唤醒负责人；已获持续跟进授权且工具允许时补齐恢复安排。子任务不扩大自动化授权；没有恢复机制就保存活动对象、待回收结果和继续入口，明确不能自动恢复，不写成完成。记录 pause 或 cancel 不得被解释为已暂停或已终止运行中的子任务。

唤醒后读取 Work 与一次紧凑状态，对完成、失败或阻塞的变化读完整结果并推进。完成、取消或跟进失效时停用所属恢复安排，更新记录。保存 Work 或 Inbox 不等于已建立检测或订阅，自动跟进必须有实际工具或运行代码承担。

## 平台能力与权限差异

自动化和新任务路径可能具有不同的能力或权限。遇到不一致时核对实际任务、项目、工具返回与授权范围；保存可重现的证据，不把一次异常扩展成所有路径的永久禁令，也不通过更换工具绕过限制。使用者的平台不同，应在本适配层记录本地差异，通用方法保持独立。

## 收尾

负责人读取完整结果并作交付判断，更新 Work，按需要归档完成的任务，停止属于本工作的自动化，清理可确认归属的临时资源。用户看到的最终报告围绕结果与证据，不围绕内部任务编号和轮询过程。
