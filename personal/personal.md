# 个人笔记

个人笔记分为 `Capture`、`Synthesis` 和 `Concept`。它们描述内容在思考中的角色，不是成熟度等级，也不规定文档格式。

## 存放位置

```text
personal/
├── inbox/
├── captures/
├── syntheses/
└── concepts/
```

`inbox/` 是个人 Chief of Staff 的轻量操作入口，不属于笔记分类。实际事项只写在可直接阅读的 [`inbox/inbox.md`](inbox/inbox.md)；本机 Web App 在运行时读写这份 Markdown，写法与维护边界见 [`inbox/schema.md`](inbox/schema.md)。

每台设备直接使用相同结构，但可以自行选择如何同步、备份或加密其中的内容。公开仓库的忽略规则本身不提供这些能力。

## 三种产物

### Capture

Capture 保存事件、观察、摘录和当时产生的想法。重点是低摩擦地保留当时发生了什么以及必要语境，而不是先把内容整理成熟。

### Synthesis

Synthesis 把一个或多个事件、已有 Concept、其他材料和自己的思考结合起来，形成具体内容产物。它可以是一段解释、一项判断、一份报告、一篇文章或其他适合当前目的的内容，不要求进一步抽象成普遍模型。

### Concept

Concept 保存可跨事件或情境复用的底层思想、模型和思考方法。关于如何思考的 meta-concept 仍然是 Concept，不需要增加第四层目录。

三者可以相互引用，也可以独立存在；一个来源可以产生多个结果，一个结果也可以综合多个来源。内容可以直接写入它实际所属的目录，不需要先补齐链路，也不需要为了改变角色而移动或改写旧文件。

## Agent 怎样使用

只有用户明确要求记笔记时，Agent 才写入个人笔记目录。项目讨论归所属项目，工作空间自身的讨论归工作空间项目；`inbox/` 按 Chief 职责维护，不属于笔记目录。

Agent 根据当前问题选择需要的内容。通常可以先搜索相关 Concept，需要理解形成过程时再读取 Synthesis，需要核对原始事件时再查看 Capture；这只是减少无关读取的经验顺序，不是强制协议。

创建和修订笔记时，不强制标题、字段、章节、文件名、元数据或引用格式。应保留多少语境、来源和边界，由内容及其用途决定。能够帮助未来理解的来源关系可以用普通链接或正文自然说明，不需要维护统一 schema 或手写双向索引。

Capture 可以保留当时的原貌并追加后续更正；Synthesis 和 Concept 可以直接修订，也可以在含义明显变化时另建内容并相互链接。选择取决于是否仍需要保留旧观点，而不是固定的版本流程。

首期只依赖普通文件、链接和搜索。只有实际使用暴露出明确问题时，才考虑 frontmatter、全局 ID、索引、知识图谱或自动采集等额外机制。
