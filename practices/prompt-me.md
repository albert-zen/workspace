# Prompt Me 与 Prompt Yourself

这两件事用的是同一套方法——**动工前先从验收倒推，把目标、边界、前置条件和容易“看起来对其实坏了”的坑全部想透**。差别只在要不要停下来交给我复制。

## 1. 先想清楚三件事

1. **做完了能看到什么？** 查明我想改变什么、哪些决定必须守住、哪些细节可以放手给执行者选。重点揪出容易漏掉的坑：哪种结果看起来对、其实可能坏了？哪条失败路径或产物能一锤定音？
2. **需要什么条件和证据？** 从验收结果倒推需要的命令、测试、样例数据、改动前基线或权限。能查到的写成具体入口；需要提前准备或申请的写清用途和缺失时的限制。
   - **UI 改动**：写清同步骤、同数据、同窗口尺寸下的改动前后对比截图与交互验证要求。
   - **需要打分或独立评审**：写清评分对象、尺度、通过阈值，以及是否需要独立 Agent 看同一固定版本并列出模型、分数与依据。
3. **只问真正影响方向的问题。** 可逆细节直接给合理默认值，标明哪些是我定死的要求、哪些是建议；只有缺一个会改变目标、验收或授权的决定时才问我，并带上推荐。

## 2. 两种用法

### Prompt Me（手动停点：交提示词给我，先别动手）

当我明确说「Prompt Me」时，你的交付物不是直接把活干完，而是**交给我一份完整、可直接复制给执行 Agent 的提示词**。这一轮可以查代码、Work、环境和工具取证，具体实施留到我发出那份提示词后再开始。

提示词按任务大小写得紧凑自然（简单任务几句就够），涵盖：目标与上下文入口、必须守住的边界、前置条件、验收方式与交付证据，以及中途若需要我拍板应停在哪里。

### Prompt Yourself（自我装填：想透标准后直接开干）

当我明确说「Prompt Yourself」，或者你接手了一个**复杂、模糊、高风险**的任务准备动工时，不用停下来等我复制提示词——先按上面三件事给自己（或即将派发的子 Agent）把执行边界、前置基线、防坑点和验收证据收拢清楚，**然后直接照着推进执行**。
