# 图形化呈现

图形化产物帮助用户理解关系、比较方案、核查证据或作出决定。开始时用一句话确定它要支持的判断，再选择信息与交互。默认视图应当直接说明主要内容，来源与细节按需展开。

用于任务验收时，沿规划中的核查路径组织：预期结果、当前可观察现象、必要操作和证据入口放在一起。用于过程理解时，从任务上下文呈现有效决定、DAG 进展、咨询问题和下一步，不把完整历史直接铺到页面上。

结构与依赖用图，变化过程用时间线，方案比较用表，真实数值关系用图表。每个区域应增加理解所需的信息；没有意义的指标、装饰性标题和重复状态应删去。

## 页面可读，来源可查

一次性 HTML 报告默认采用无需构建的单文件，内嵌 CSS 与必要脚本，核心内容离线可读；外部资源按已知网络与隐私条件使用。默认视图直接给出主要结论，细节按需展开。桌面和窄窗口都能阅读；重要信息与操作支持键盘、触屏和可见焦点，状态不只依靠颜色或 hover。

标明内容适用时间、必要的精确对象和来源，区分事实与建议。数据报告保留指标定义、单位、范围、样本量与原始来源，不能用视觉编码夸大差异。视图派生自文件、代码、数据或判断记录；视图更新不能假装事实源已经改变。可编辑界面应让用户知道修改会写到哪里，遵从具体应用已有的保存和冲突协议。

私有报告放在对应事项的 artifacts 中，不嵌入凭据或完整私密 trace。生成后打开可用入口，聊天仍然给出核心判断与绝对路径。

## 按场景进入应用

通用页面只承担呈现；应用各自维护代码、schema、保存协议和测试。使用前读取相应入口，避免把展示结果当成已写回事实源。

| 场景 | 入口 |
| --- | --- |
| 解释问题并审阅实际文件改动 | [HTML 审阅工作台](html/review/review.md)：真实 diff、批注与编辑、接受/拒绝、response 及显式 check/apply |
| Chief 呈现关注事项，编辑 Inbox 或阅读 Work | [Personal Inbox](html/inbox/README.md)：规范 Markdown、固定状态、Work 阅读及 revision 冲突处理；关注内容见 [Inbox](../collaboration/chief/inbox.md) |
| 可探索的架构、流程、时序、数据流或生命周期图 | [Archify 接入](../../references/communication/archify.md)：本地 Skill、结构化输入、HTML/SVG、校验与导出 |

Matt Pocock 的 [HTML Report Format](../../references/matt-pocock-skills/skills/engineering/improve-codebase-architecture/HTML-REPORT.md) 提供架构报告、before/after 与以图承载信息的方法，按需参考。

普通解释可直接使用单文件页面、Mermaid 或表格。新场景先独立实现，只有确实共享语义与交互时才按应用契约提炼组件，不将所有页面套入审阅应用。
