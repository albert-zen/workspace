# 长期记忆（`memory/`）

`memory/` 存放 **AI 认为值得跨任务留存的长期记忆**。它由本机独立私有 Git 仓库管理，不随外层工作空间公开提交。

它和另外两类材料的边界很清楚：
- **单次任务的上下文、进展和交付流水**留在 `agent-data/` 的 Work 文档里，不进 `memory/`；
- **我自己的个人思考笔记**留在 `personal/`（见 [个人笔记](../personal/personal.md)），不混进 `memory/`；
- **跨项目可公开复用的工作方法**沉淀到工作空间规则，私有环境、内部系统细节、反复踩过的坑和具体背景留在 `memory/`。

## 1. 何时查阅与检索

当你判断**之前干过活的 Agent 可能留下过有用记忆**时（例如特定服务器与运维入口、内部系统约束、环境排障坑、历史方案教训或长期有效的协作背景），先翻一下 `memory/`：

- **先靠清晰文件名检索**：先列 `memory/` 目录或按主题词搜索文件名/内容，命中后再打开对应文件，不要每次任务都盲目通读全部记忆。
- **按需维护轻量 `INDEX.md`**：文件名本身能一眼看出范围时，不需要硬建索引；只有当文件数量增多、或仅靠文件名不足以判断里面有什么时，再由整理流程维护一份一行一条的 `memory/INDEX.md`（文件路径 + 一句话覆盖范围），不要让日常执行 Agent 顺手维护索引。

## 2. 执行中顺手记录（不打断主线）

执行具体任务的 Agent **不要在中途分心去重构或整理整个 `memory/` 目录**。

如果你在干活时意识到某件事值得留给未来的 Agent（比如踩出一个非显而易见的环境大坑、核实了某台机器的真实入口和禁区、或明确了一条跨任务有效的约束），花几秒在暂存目录 `memory/inbox/` 记一条极简速记即可（如 `memory/inbox/YYYY-MM-DD-<主题>.md`），写完立刻回到当前任务。

每条速记只写 4 样，不贴大段日志：
- **结论 / 事实**：未来 Agent 直接能用的一两句话；
- **适用范围 / 触发条件**：什么项目、系统或场景下生效；
- **来源**：日期、对应对话或 Work 路径；
- **为什么值得留**：不记下来未来会踩什么坑或白干什么活。

## 3. 后台定期 / 按需整理记忆

除了执行中顺手记，更完整的积累方式是由一个独立的整理 Agent 定期或不定时在后台运行，统一回看近期工作并整理 `memory/`。具体如何定时触发留给所用的 Harness 决定，但整理本身遵循以下原则：

- **扫描来源**：近期 AI 对话记录、近期更新或归档的 Work 文档与 `intent.md`，以及 `memory/inbox/` 中的速记条。
- **严格准入（防变流水账垃圾堆）**：只收**“未来新任务会再次用到、且在代码仓库或 Work 入口里不容易直接查到”**的内容。单次交付的 commit 列表、测试计数、改动过程流水一律不进 `memory/`。
- **优先归并、及时淘汰**：新信息尽量合并进同主题的已有记忆文件，同步更新或删除已经过时的旧事实，避免不断制造碎片文件；文件名保持直白、便于检索。
- **增量水位线**：记录上次已扫描到的时间点或处理进度，避免每次全量重复扫旧记录；已吸收的 `memory/inbox/` 速记处理完后移走或删除。
- **强制溯源与版本保护**：每条新增或改写的记忆保留来源线索（日期、对话或 Work 路径），不把一次临时试探脑补成长期铁律。每次整理结束后，在 `memory/` 独立 Git 仓库里做一次清晰的本地提交（写明新增、更新或清理了哪几条记忆），方便随时 `git diff` 核查或回滚。

## 4. 后台整理任务最小提示词骨架

后续配置定时或手动整理 Agent 时，可直接以此为提示词主干（按当时 Harness 补充读取对话的工具说明）：

```text
请按 practices/memory.md 的原则，增量整理本工作空间的长期记忆：
1. 读取上次整理的增量水位线（若无则从最近 24–72 小时起），检查近期 AI 对话、agent-data/ 中有更新的 Work 与 intent.md，以及 memory/inbox/ 里的速记条。
2. 只提炼“未来新任务会再次用到、且代码库/Work 入口不易直接查到”的稳定事实、踩坑解法、环境约束和长期背景；拒收单次交付流水。
3. 合并到 memory/ 下对应主题文件（优先复用与更新已有文件，删除过时内容）；每条保留日期与来源线索；若文件数或标题已不便直接检索，同步更新 memory/INDEX.md；清理已吸收的 memory/inbox/ 速记。
4. 在 memory/ 独立 Git 仓库内提交本次整理变更，并简洁汇报：新增/更新/淘汰了哪些记忆、是否有拿不准需要用户确认的冲突项。
```
