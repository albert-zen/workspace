# 工作工具与流程

人用 Inbox 安排关注，Agent 用 Work 保存工作上下文。`work` 处理登记、关联、版本和收尾；目标、授权、验收及正文里的判断由人和 Agent 负责。

## 操作入口

运行 `work` 按意图选择操作，`work 操作 --help` 查看参数。未安装时用工作空间根目录的 `bin/work`，`bin/work install` 可建立本机入口。日常用“项目/事项名”，身份和版本不手填；重名或歧义须明确目标。

`add` 只记想法；`start` 建立或复用 Work，带目标可一次新建，参数以 `work start --help` 为准。需要开发隔离时按 start 帮助创建工作树，并在返回目录工作。`resume` 只读，不开始任务或改负责人；标准章节只折叠历史，旧格式或结构有歧义时保留全文，`--full` 总是全文。

当前正文用 `work edit '项目/事项'` 取得副本，修改后执行输出的 `work save <副本路径>`；版本由副本携带，冲突时保留双方内容。`save` 不保留被覆盖正文的全文版本；重要旧决定若没有来源记录，先用一次 `record --text` 留下必要的旧决定、变更与理由，再 `edit` 取得新副本；已有出处则引用即可。

计划用 `plan edit/save` 维护版本，`plan save --reason` 同时保存变更理由，不再为同次计划修改另写一条 `record`。可用 `plan show --version`、`plan history` 查看旧版本和变更。计划步骤可选用 checkbox，并以语义名称绑定步骤；依赖形成 DAG，工具校验不存在的节点、重复名称和环。摘要只在同一写入操作明确提供时更新，不从任意正文修改自动生成。

`record` 只提交一次进展内容，工具同时替换当前推进并追加执行历史，时间和计划版本由工具填写，历史只追加；自动生成的当前视图与历史不是两份手工记录。它不更新事项说明或项目设计文档。`history` 读取执行记录，`resume --full` 展开文档历史；两者都不能恢复未曾记录的旧正文。

`pause` 与 `cancel` 更新 Work，并同步 Inbox；`pause --needs-user` 进入 Needs you，普通 pause 进入 Waiting。`cancel` 隐藏 Inbox 条目但保留记录，`reopen` 恢复 In progress。`finish` 写入结果和记录、更新 Inbox 为 Done 并清理可确认归属的 Git 资源。上述命令只维护记录和用户视图，不控制、中断或暂停 Agent、平台任务或调度；调度与停止由 Agent 自行管理。未完尾项保留，原因解除后可继续 finish。

## 状态与资源

`handoff` 登记负责人，不代替派发。个人 `arrange` 调整关注、顺序或隐藏，不改变共享工作的状态。

`add-worktree 项目/事项 --name 用途` 随时创建并关联第一个或后续工作树；第一次用 `--repo` 指定仓库，之后唯一时自动沿用。默认目录是工作空间下的 `dev/worktrees/<仓库>/<事项-用途>/`，可用 `--path` 指定其他位置。同名复用，显式参数冲突则拒绝；`--at 提交` 从固定提交创建新分支，`--base` 指定收尾时核对的合入分支（默认 main/master）。`start --worktree` 是创建名为“开发”的工作树的快捷入口。`resume` 显示各工作树名称与路径，`finish` 逐个检查清理；已有资源仍用 `link` 登记。`release` 只解除本事项占用，不表示资源在原平台已关闭，也不新增删除授权。

自动清理限于本事项创建、干净、已合并且无其他使用者的 Git 资源。主目录、共享或已有资源、独有成果均保留；平台任务、PR、远端分支、部署和消息通过对应工具按已有授权处理。

事项完成与尾项清完分别记录，工具成功不证明业务目标实现。文件操作中断按返回入口 `recover`，不强行覆盖外部修改。程序调用用全局 `--json`，其他数据根用 `--root PATH`，均放在操作名前。
