# Inbox、变化同步与呈现

Inbox 是面向用户的关注视图：现在有什么值得看、为什么、下一步是什么、从哪里继续。它以 Markdown 为内容入口，程序负责读取和渲染，人与 Agent 都能够使用。

全局事项索引用于 Chief 恢复与取得背景；各项 Work 保存事项说明与执行事实；Inbox 只呈现当前值得用户看到的部分。它们可以引用相同事项，但不分别维护完整计划。Chief 的排序和解释属于独立判断，应当可以追溯到来源。

## 一条变化如何到达用户

来源变化 → 检测并取得新内容 → 更新可确定的事实、标出受影响的旧判断 → Chief 判断意义与下一步 → 保存关注内容 → 程序校验并呈现。

程序负责变化检测、格式校验和已有明确事实的呈现；涉及意图、优先级或自然语言状态推断时由 Chief 判断。判断期间来源再变须重新核实，无法更新时标明时间与待核实范围。检测不会增加授权，文档里的行动建议不等于用户已批准。

## 关注内容怎样写

每项摘要写清当前判断与下一步，必要时补足问题背景，让用户不打开 Work 也能判断是否需要关注；不限制字数或句数，不为简短丢失推荐的具体内容；需要用户决定的写清问题、影响与推荐，完成项只保留结果与有价值的入口。主动暂缓、尚未排实施的事项不得混写成正在推进。负责人仍在跟进且无需用户处理的外部依赖留在进行中，说明等待对象和下一步；确需用户解除的阻塞进入需要我。

Inbox 概述当前判断，展开、详情及复制直接读取 Work 的“事项说明”和“当前推进”，不另存第二份事项描述。Work 按[共同上下文](../context.md#先读懂当前工作再按需取得细节)提供目标、方案、阶段和执行依据。测试数量、提交号、内部任务 ID、Review 轮次和反复验证过程默认不进入 Inbox；只有影响可用性、风险或用户决定时，用普通语言说明影响并链接证据。既不以技术活动代替进展，也不为简洁掩盖未交付或未核实的部分。

例如进行中的实验可写：“隔离候选与复审完成。下一步验证完整任务收益，再决定是否提供实验入口。”准确对象和检查报告留在 Work。负责人维护 Work，Chief 核对来源后更新 Inbox；改写摘要不额外复制一份执行计划。

按[咨询流程](../work.md#设计问题逐层咨询)仍需用户判断的问题进入待决定区域，写明选择、影响与推荐，链接完整分析；已能在工作内部决定的，不重复生成待办。

推荐次序与阶段目标来自 Chief 的综合判断。预计用户投入时间能够帮助安排时给出估计及其依据，明显不确定时保留范围。较长的排期分析留在关联记录中，不为展示它改变当前 Inbox 的固定格式。

分类采用用户语义：等待中为 backlog，进行中为 in progress，需要我为需用户解除的 blocked，已完成容纳 completed / archived。Work 的普通 `pause` 同步为 Waiting，`pause --needs-user` 同步为 Needs you；`cancel` 隐藏 Inbox 条目但保留记录，`reopen` 回到进行中，`finish` 回到已完成。同步只改变记录与用户视图，不控制、中断或暂停 Agent 和平台任务。具体边界及与现有 Markdown 章节的映射以[状态契约](../../../personal/inbox/schema.md#四个固定状态)为准。

优先显示重要变化、阻塞与待决定事项；交付项提供既定核查入口和仍需判断的部分。普通活动不必逐条出现，待处理区域可以为空；按有意义的判断汇总，不把子任务数量当作用户工作量。

用户通过界面输入的反馈也要回到相应事实源或负责人。修改 Inbox 摘要只改变该摘要，不代表项目计划已经修改；已经完成转交和落实后，才相应更新执行状态。

## 当前使用现有 Markdown 应用

当前内容文件是实际工作空间中的 `personal/inbox/inbox.md`。写法与固定状态遵从 `personal/inbox/schema.md`，应用入口是 `practices/communication/html/inbox/README.md`。使用前读取它们；规则重写不改变现有解析器契约。

需要打开界面时，按应用 README 启动或复用本机服务。复用前核对应用身份与 `/api/inbox` 的 `sourcePath`，不能只凭端口或 HTTP 200 认定正确；端口被占用时使用空闲 loopback 端口。应用不可用则说明原因并使用 Markdown。在 Codex 中通过当前可用的打开工具呈现入口。

现有应用提供 Markdown 的读取、显示和编辑，以及关联 Work 的阅读。本稿不假定它已经订阅全部 Work 变化、运行 Chief 或自动生成综合判断。没有这条链路时，Chief 在恢复及处理相关事项时核实来源、更新 Inbox，再由应用呈现；无法做到的自动新鲜度要明确说明。

全局索引及其维护位置见 [Chief](README.md)。Inbox 摘要只保留影响理解的短说明，不向受约束的 Markdown 随意增加字段。

使用应用保存时遵从已有 revision 冲突处理；直接编辑文件时也要读取最新内容，保留其他人的更新。合成示例放在测试材料里，不向真实 Inbox 写入假事项。

这份规则定义期望行为与当前工作办法，不等于已经部署后台同步。同步频率和通知方式按用户需要与工具能力约定，不在所有事项上强加同一个周期。
