# 人与 Agent 共用的上下文

Work 是一项持续工作的共同入口。它保存目标、决定、进展与来源，让人看懂、让任何 Agent 接手。简单提醒已有足够信息时不另建空文档；内容变长再链接方案、节点或证据，不为人与 Agent 各维护一套计划。

## 先读懂当前工作，再按需取得细节

Work 的当前内容分为以下部分，Inbox 直接读取事项说明：

- `## 事项说明`：为什么做、期望结果、范围和验收；本项设计的有效决定与依据，或指向其权威来源的链接。
- `## 当前计划`：可选。方案、理由、步骤及依赖；由 `plan edit/save` 维护版本。
- `## 当前推进`：当前阶段、已确认进展、证据、剩余工作与待决定点；短任务几句话即可。

失败、限制、可用入口和本机／合并／安装／部署的区别必须在当前概览可见。精确提交、配置、测试和日志放后文或来源链接，影响当前判断时说明其意义。不能用“通过”掩盖验证范围或例外。

有效约束、决定、未决问题及必要材料留在当前正文，不能只放在会被后续进展替换的“当前推进”中。`## 历史记录` 保存过去过程；正文、计划与进展各用哪个命令维护，以及历史保留范围，见[工作工具与流程](workflow.md#操作入口)。完成前写清已核实的业务结果、证据与余项。

## 各环节共同遵守的最少约定

复杂工作通过正文或链接取得下列事实；不适用的省略，不填空表：

- 目标与约束：已确认决定、来源、用户指定的模型／环境／预算，以及待验证假设。
- 执行：方案、节点及依赖、负责人、计划与实际配置、当前环境和精确对象、阻塞或偏差。
- 验收与交付：预期现象、验证与停止条件、结果和证据、人的最快确认路径、限制和剩余安排。
- 派发与咨询：角色、直接上级、项目规则、目录和固定对象、写入范围、交付位置及返回通道；Reviewer 另列范围、轮次和只读边界。

行动前核对派发范围；无上级时由负责人直接承接用户决定，不虚构层级。调度与决定回流见[事项推进](work.md#调度与回收)，无需为取得派发事实重读整套方法。

## 主动整理与压缩

决定变化、阶段切换、准备派发或交还，以及预计压缩时，合并重复信息，更新权威来源。设计修订说明改变了什么及原因，旧方案保留必要的历史出处；已有记录只引用，不另抄一份。保存方式遵循工具实际支持的历史范围，不把假设改成结论，也不删除偏差来制造成功。

当前记录优先呈现目标、有效决定、进展、阻塞与下一步。检查另一位 Agent 能否沿入口知道做什么、为什么、怎样验收及何时咨询。Harness 摘要只能辅助，不能替代文件；无需每条消息后抄写历史。

## 恢复与新鲜度

先用 `work resume` 取得当前正文和关联资源，再核实下一步涉及的文件、提交或平台状态。接手、实现或修改设计前，沿入口核对相关意图、有效决定和待讨论边界；缺口影响当前判断时才追溯来源，仍无法确认就保留未决并在依赖它的决定前咨询。没有具体缺口不重读全部历史；上次核对位置可缩小范围，但不证明来源没变化。

无法核实时区分最后已知事实与未知，不把“未见消息”写成“尚未完成”，也不用旧摘要代替新授权。独立工作可继续，依赖缺失事实的决定等核实后再作出。

## 事实归属与设计意图

同一事实只维护一个当前来源：项目长期事实在项目文档，本项决定在 Work，个人材料按[工作空间](../../workspace.md)存放。设计讨论形成会影响后续实现或取舍的意见时，更新其所属来源，保留目标、理由、约束、方案及确认状态；Work 链接已有设计、代码、报告、所需 memory 和原始材料，不重复维护正文。简短事项一段话即可，不为每次讨论另建文档。

区分用户原话、转述、Agent 建议与已确认决定，保留可取得的来源消息、任务或文档位置；只取得转述就说明证据边界，不补造原话或推定认可。简短认可须能找到所指方案及认可范围。交接或归档前确认有效设计沿入口可达；转为项目长期设计时迁入项目文档，Work 留链接和交付状态。Chief 的综合判断注明依据，不覆盖原始事实。

用户直接给下层的新决定立即生效并按[咨询路径](work.md#设计问题逐层咨询)回流，不因此转移负责人或另建计划。原话是否留存由用户或维护流程按需决定，Work 正文不承担独立的原话档案。

Markdown 保持人可读；机器字段仅在确有解析需求时规定最少格式并校验。程序能维护已记录事实，不能从任意正文保证推断正确状态。跨环境无法读取原记录时才生成一次性交接材料；长期来源仍只有一份。Inbox 视图规则见[Inbox](chief/inbox.md)。
