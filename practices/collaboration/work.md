# 把一项工作推进到结果

负责人从理解目标承接到交付与反馈；事项可以是开发、调查、文章或个人事务。工具承担工作维护，负责人判断方案、授权和验收。本文处理规划、分工与咨询，不是每次运行 work 前的操作手册。

## 与用户形成当前方案

先查相关背景，理解想改变什么、为何做及已有约束。目标含糊时帮助定义问题和取舍；能查到的事实自己查，重要方向由用户决定，边界内的实现选择直接推进。

讨论也可用代码、文档、数据、外部来源或小试验取得证据；围绕影响选择的问题调查，足以决定就收敛。建议一次呈现主要选择、依据与推荐，不逐题盘问或逐步审批。区分已确认决定、建议和假设；假设安排早期验证，持续工作写回当前 Work。

借仓库澄清设计可参考 [Grill With Docs](../../references/matt-pocock-skills/skills/engineering/grill-with-docs/SKILL.md)，仅有想法可参考 [Grill Me](../../references/matt-pocock-skills/skills/productivity/grill-me/SKILL.md)；需要相应提问方法时再读。

## 在规划时设计验收

方案说明完成后的可观察现象，以及人最快确认的入口和步骤。例如保存功能：修改、保存、重开内容一致；并发修改时保留输入并提示冲突。研究则给结论到来源的核查路径。

分别记录自动检查、实际交付与用户验收；检查通过不代表已交付。验收条件写进执行节点，变化时保留依据，不在结束时另造容易通过的标准。简短任务几句话即可，不必制造页面或测试环境。

## 把方案变成执行 DAG

多步工作按可验证的结果切分并标明依赖，节点写清交付、依据、范围、验证和停止条件；跨任务引用时用稳定短名，简单顺序用列表即可。需要由工具读取和校验的计划，使用可选 checkbox 步骤和语义名称绑定依赖，形成无环 DAG；执行状态和历史由工具追加记录，正文仍负责解释判断与验收。

优先做穿过真实边界的纵向切片，再并行扩展。例如先确认保存语义，再打通写入与冲突，之后并行接界面和验证旧文件，最后集成验收。依赖未稳定时先明确接口或缩小切片，不让各 Agent 猜测。

节点内部可循环实现、测试、Review、修复和清理，不借加固扩大需求。新证据推翻假设时修订计划并保留原因；改变用户确认的目标或取舍须说明影响再决定，不把未完承诺不断拆成后继事项。

需要切分方法时参考 [To Tickets](../../references/matt-pocock-skills/skills/engineering/to-tickets/SKILL.md)；跨多会话且目标仍模糊的大型探索才参考 [Wayfinder](../../references/matt-pocock-skills/skills/engineering/wayfinder/SKILL.md)。

## 调度与回收

有独立上下文、并行执行或独立判断的收益时，再按当前授权和 Harness 能力委派；任务太小或依赖紧密就自行完成。角色与模型分开考虑，遵守指定配置。大型工作由主线程维护整体计划和集成，复杂切片可有局部负责人，不为短任务搭层级。

按[派发约定](context.md#各环节共同遵守的最少约定)提供有关背景、固定对象、写入边界和回收通道。并行写入用隔离工作树或明确不冲突的分工；共享 Work 由负责人汇集或排定写入顺序。只读任务仍受项目规则约束。

下级向直接上级返回完成、失败或阻塞事件，包含节点、状态、报告位置及适用的 Review 轮次。完整报告保留精确对象、证据与未解决项；没有推送通道时由负责人实际等待或读取，不能留在无人查看的位置。普通事件不逐层广播给 Chief。

负责人读取完整结果、更新当前记录，按证据裁决、修复或放行依赖。阻塞要区分事实缺失、外部条件和取舍问题，能在授权内解决就继续，其余说明影响和可选路径；完成信号本身不是验收。

## 设计问题逐层咨询

先查任务入口及事实，仍无法判断时带候选方案、约束和推荐咨询直接上级。有背景且在委托范围内的上级作决定；否则继续查证或向上咨询，直至 Chief。只有缺用户意图、重要取舍或授权时才整理到 Inbox；单任务无上级时直接与用户讨论。

咨询只传有关问题与来源，不复制全部历史；等待只暂停依赖节点。答复写回上下文，负责人同步受影响的执行者、计划与验收。

用户直接给下层的补充立即用于判断，保留准确原意与来源并通知负责人；影响全局的决定回流 Chief。直接沟通不转移负责人，转移时明确承接者、对象与后续入口，避免双重计划。

## 用反馈完成工作

代码或行为规则修改按[Review](review.md)独立审查，工程验证见[验证方法](../engineering/verification.md)。负责人按需求裁决 findings，局部问题修回节点，架构或目标假设错误回到方案；不把个人偏好升级为需求。

集成前核对对象、接受的问题、证据与操作授权；Review 不增加发布或合并权限，已有授权不重复确认。按预定标准核查，交付可用入口、证据、限制及需用户决定的事项，不虚构用户验收。

保存实际业务结果后通过工具收尾，处理返回的尾项；暂停、取消、完成如实表达。Work 状态同步 Inbox 只表示记录和用户视图，不表示 Agent 已被暂停或终止；运行调度由 Agent 自己管理。反馈沿同一事项继续。回顾可产生工具、方法或知识改进，也允许没有新规则或 memory。
